MIRAGE: Multimodal Image Retrieval &
Attribute-Grounded Engine

An open-vocabulary, context-aware image search engine utilizing VLM dense captioning (Moondream) and CLIP visual reranking for zero-shot image retrieval using natural language.

Version 1.0.0
Moondream 2 VLM
OpenAI CLIP
ChromaDB (HNSW)
§ Overview

Key Features

Compositional Attribute Binding

Uses a Vision-Language Model at indexing time to correctly associate colors, textures, and shapes with their specific objects, resolving standard CLIP's noun-adjective binding confusion.

Context & Location Awareness

Retrieves images using environmental details (e.g. offices, city streets, outdoor parks) and weather conditions (e.g. rainy night, sunny summer day) captured during captioning.

Vibe & Style Inference

Supports abstract queries like "cozy living room" or "adventurous outdoor gear" by mapping aesthetic descriptions into dense semantic vectors.

Dual-Stage Retrieval

Combines fast semantic indexing (ChromaDB) with local visual verification (CLIP reranking) to achieve sub-second query latency even at scale.

§ System Design

MIRAGE implements a dual-stage search pipeline. The query runs through a semantic path to fetch candidate lists, which are then passed to standard CLIP for visual grounding and final reranking.

§ Pipeline Logic

Implementation Details

Part A — The Indexer (Offline Ingestion Pipeline)

  • 1

    Dense Captioning (Moondream VLM)

    Every image in the database is processed through the Moondream Vision-Language Model. It generates a detailed description covering objects, colors, settings, and styles. This translates the visual binding problem into a textual one—the VLM does the heavy lifting of correctly binding visual attributes to specific nouns.

  • 2

    Text Semantic Embedding

    The VLM-generated caption is encoded into a dense 384-dimensional semantic vector using the all-MiniLM-L6-v2 model.

  • 3

    Standard CLIP Ingestion

    The image is simultaneously passed through standard OpenAI CLIP (clip-vit-base-patch32) to produce a 512-dimensional visual feature representation.

  • 4

    Vector Database Storage

    The semantic caption embedding is indexed as the primary search vector in ChromaDB. The image file path and the precomputed 512-d CLIP visual embedding are stored inside the record's metadata.

Part B — The Retriever (Online Search Pipeline)

  • 1

    Dual Query Embedding

    When a user inputs a natural language search query, it is encoded twice:

    • Embedded with all-MiniLM-L6-v2 for semantic caption filtering.
    • Embedded with standard OpenAI CLIP for visual-text reranking.
  • 2

    Candidate Retrieval (Top-N)

    ChromaDB is queried using the semantic caption embedding to return the Top-N (default: 20) candidates. This initial pass acts as a coarse filter to remove incorrect compositional bindings (e.g. filtering out "red shirts with blue pants" when looking for "blue shirts with red pants").

  • 3

    CLIP Visual Grounding

    For the 20 retrieved candidates, the retriever calculates the exact cosine similarity between the query's CLIP text vector and the candidate's precomputed visual feature vector.

  • 4

    Weighted Score Fusion

    The final rank is determined using a weighted sum of the caption similarity and the CLIP visual similarity:

    $$Score = (w_{caption} \times Sim_{caption}) + (w_{clip} \times Sim_{clip})$$ $$[Sim - Similarity]$$
§ Setup

Getting Started with MIRAGE

1. Clone & Install Dependencies

zsh — setup
Copy
git clone https://github.com/kanaad-lims/mirage.git cd mirage pip install -r requirements.txt

2. Set Up API Keys

Create a .env file in the project root and add your Moondream VLM API Key:

.env
Copy
MOONDREAM_API_KEY=your_api_key_here

3. Index Your Images

Place your images (e.g. .jpg, .png) inside the data/images/ folder and run the builder script. Features are cached automatically for skip/resume resilience.

zsh
Copy
python -m indexer.build_index

4. Try Out Search Queries

Search your visual collection using the retriever CLI. The script stitches matching results into a horizontal preview grid.

zsh
Copy
python -m retriever.search a red coffee mug on a white desk

§ Performance

Scalability Analysis

When scaling to 1 million+ images, MIRAGE maintains sub-second query latency by exploiting sub-linear indexing algorithms and localized compute bounds:

  • Sub-linear Search (HNSW Indexing)

    Primary filtering runs on ChromaDB's HNSW (Hierarchical Navigable Small World) index, completing approximate nearest neighbors search in logarithmic time O(log M).

  • Constant-time Local Reranking

    CLIP visual similarity math is strictly bound to the Top-N (e.g. 20) candidates retrieved in Stage 1, eliminating the need to evaluate 1 million images at search time.

  • O(1) Offline Precomputation

    Generating captions and image vectors is a one-time offline process. It runs during ingestion, and once stored, requires zero real-time CPU/GPU computation.
